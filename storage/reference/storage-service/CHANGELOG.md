# Changelog

All notable changes to storage service will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Fixed

- OMPE-114478: Fix duplicate scheme separators in S3 and Azure Blob endpoint URLs generated by the Helm chart.
- OMPE-115512: Ensure consistent URI pattern handling across layers.
- OMPE-113620: Preserve percent-encoding of unsafe path characters after URL normalization.
- OMPE-113502: Handle S3 object deletion events with a missing ETag in the SQS subscriber.
- Strip the storage-core S3 test module from vendored sources before bundling the container's vendor archive to avoid malware scanner false positives.

### Changed

- OMPE-105840: Publish the GitHub snapshot as tested: content rewrites move into the source, the prepare script only repoints dependency sources, and new merge-request jobs build and test the published layout.
- OMPE-105840: Update storage-core to 0.11.0-alpha.3.
- OMPE-105840: UCC proxy TLS verification is now disabled only when `UCC_PROXY_SSL_VERIFYCERT` is set to `insecure`. The values `false` and `0` no longer disable it; deployments that use them to reach a proxy with a self-signed certificate must switch to `insecure`.
- Restore the header forwarding Helm setting to `observability.headers.forward`.
- Rebase the container on `nvcr.io/nvidia/distroless/cc:v4.1.5` (from `v4.1.4`) to pick up the OpenSSL security update (`libssl3t64` and `openssl-provider-fips` 3.5.7-1~deb13u2 to 3.5.7-1~deb13u3).
- OMPE-113620: Enable URL normalization by default. It changes which object some addresses resolve to; see `docs/helm/url-normalizer.rst` before upgrading, or set `config.urlNormalizer.enabled` to `false` to retain the previous behaviour.

### Added

- OMPE-113620: Reject invalid Azure Blob paths.
- OMPE-113363: Add retries for the permission client.
- Forward the incoming request headers listed in `observability.headers.forward` to the permission service.
- OMPE-113620: Expose the URL normalizer through the `config.urlNormalizer.enabled` chart value.

## [1.2.3] - 2026-09-28

### Added

- OMPE-104659: Serve the `IsReadOnly` and `IsVersioned` RPCs, with a per-endpoint `readOnly` setting.
- Allow deployments to opt out of serving the OpenAPI documents.
- OMPE-90246: expose the native metadata settings for the S3 and Azure Blob backends.
- Added the top-level `nvidia.omniverse.metadata.v1beta` Metadata API, served over gRPC and REST alongside the existing `nvidia.omniverse.storage.metadata.v1alpha` API and backed by the same metadata backend.

### Changed

- Updated `storage-core` and `storage-core-util` to 0.11.0-alpha.1, and `storage-core-protos` to 0.29.0-alpha.1.
- Decompose Helm chart parameter tables into individual parameter declarations in the documentation.
- Harden the Helm chart defaults: run the pod as non-root uid 1000, drop all container capabilities, and forbid privilege escalation.
- Rebase the container on `nvcr.io/nvidia/distroless/cc:v4.1.4` (from `v4.1.2`) to pick up libc6 security fixes.

### Fixed

- Restore the missing `httpProxy.tls.certManager` section in the Helm values file.

## [1.2.1] - 2026-08-31

### Added

- OMPE-98507: Expose endpoint-specific versioning support configuration for S3 and Azure Blob backends.
- OMPE-103415: Record a `created_timestamp` metadata entry when a resource is first created via write / copy / move / create_folder, and best-effort remove it when the resource is deleted.
- OMPE-101070: Shared redis cache tier for the Metadata API.
- OMPE-92920: Filter `ListRoutes` and url-remapper aliases by the caller's permissions.

### Fixed

- Helm chart: an explicit `config.storage.azureBlob.poolMaxIdlePerHost: 0` now renders `pool_max_idle_per_host = 0` to disable idle-connection pooling (previously dropped as falsy); an unset value is still omitted.
- OMPE-105165: Authorize responses served from the workspace manifest cache, which previously bypassed permission checks.
- Fix an issue when URL remapper would fail a request with an unversioned resource address in the response.

### Changed

- OMPE-100786: Batch storage event consumption and notification publishing through `BatchPublishEvents`, with a configurable client-owned request size limit.
- `Copy` and `Move` across different storage backends now return `UNIMPLEMENTED` (REST 501) instead of `INVALID_ARGUMENT`.
- Updated `storage-core` to 0.10.0, `storage-core-util` to 0.10.0, and `storage-core-protos` to 0.28.2.
- Renamed the per-endpoint `enable_permissions` / `enablePermissions` option to `permissions_enabled` / `permissionsEnabled`.
- Discovery v2alpha now advertises the REST version mount base (`/v1alpha`) instead of embedding the resource name; clients combine it with the endpoint name and the group's OpenAPI paths.

## [1.2.0] - 2026-07-17

### Added

- Apply the Postgres metadata migrations from an init container before replicas start serving; the token provisioner runs as a native sidecar (Kubernetes 1.29+).
- OMPE-92920: Per-backend and per-alias flags to hide entries from `ListTopLevelAddresses` and `ListRoutes`.
- Add a per-endpoint `enable_permissions` flag to bypass the permission layer for public endpoints.
- OMPE-92921: Expose `allow_unconfigured_endpoints` for the S3 and Azure Blob backends; when disabled, the router rejects requests to unconfigured endpoints instead of forwarding them.
- OMPE-88004: Publish synthetic `dir_created` / `dir_deleted` events derived from file events, with a `[synthetic_dir_events]` config section gating the feature and its retry policy.
- Add limit clauses to the queries in the CosmosDB backend to reduce the query request unit consumption.
- Add an option to override the consistency level for individual CosmosDB operations.
- OMPE-91252: Add support for AKS Workload Identity and EKS IRSA credentials.
- OMPE-92865: Add support for a Postgres metadata backend.
- Add support for manifests.
- OMPE-93043: Add support for reading injected AWS/Azure client credentials.
- OMPE-84310: Optional shared Redis/Valkey L2 cache tier.
- OMPE-92558: Configurable metric-name prefix.
- Expose `pool_max_idle_per_host` for the Azure backend.
- OMPE-93433: Implement `UpdateMetadataBatch` (v1alpha).
- OMPE-94253: Add support for temporary client credentials to the Postgres metadata backend.
- OMPE-92912: Add support for multiple storage event subscribers of the same kind.
- OMPE-94307: Add resource identities in storage events.
- OMPE-95289: Resolve identities for deleted objects in Azure Blob storage events.
- URL remapper: optional synthetic-folder injection for mounted child rules (`config.urlRemapper.exposeChildRulesAsFolders`).
- Add access token file service identity provider.
- OMPE-96738: Uniform GRPC load balancer implementation.
- OMPE-95482: Add client-side load balancing for GRPC connections to the Notification Service.
- OMPE-98059: Add support for batch metadata operations.
- OMPE-98172: Add standardized `observability` block to the Helm chart for configuring OTEL metrics and tracing via OTLP/gRPC.
- Add support for ingress throttling and load shedding.
- OMPE-100674: Add a mechanism to apply database migrations in the Postgres metadata backend.
- OMPE-100464: Add page size and batch size limits in requests.
- OMPE-100787: Add support for namespaces in the Metadata API.
- Implement the discovery capabilities v2alpha `CapabilitiesService`.

### Fixed

- Suppress S3 and Azure Blob folder sentinel object events from event aggregation notifications.
- OMPE-98511/OMPE-98498: Log `NotFound` and `PermissionDenied` errors at `debug` level in the `TraceErrorService` middleware instead of `error`.
- OMPE-98104: Propagate W3C trace context in outbound gRPC calls to the permission service, so permission-check spans are visible in distributed traces.
- OMPE-98678: Set `OTEL_METRIC_EXPORT_INTERVAL` to 15 s in the Helm chart to fix missing histogram panels when using the OTLP metrics exporter.
- OMPE-98018: Default the permission service gRPC endpoint to `http://permission-service:3010` when `permissions.enabled` is true and no client endpoint is configured.
- Fix an issue where TCP connections could be exhausted under stress loads in the Cosmos DB client.
- Fix Helm smoke tests: REST Copy uses `/v1alpha/.../copy` instead of removed `/v1testcopy/...`.
- Fix an issue when URL normalization wasn't applied to resource URI hostnames in the Metadata API calls.
- Fix an issue when accessing remapped addresses without a metadata backend configured would result in an internal server error.
- Fix manifest overlay reads to remap backing-object identities and authorize them against the reader.

### Changed

- OMPE-92921: Requests to unconfigured S3 buckets and Azure storage accounts are now rejected at the routing layer.
- Update storage-core to version 0.8.2.
- `ListTopLevelAddresses` hides nested mount rules, surfacing only root URL-remapping rules (when `expose_child_rules_as_folders` is enabled).
- Replace queries to CosmosDB with point reads where possible.
- Replace monads with dyn wrappers when building the middleware stack where possible.
- Bump storage-core to 0.6.0.
- OMPE-94089: Add grouping by backend ID for the Cosmos DB, DynamoDB, and Postgres metadata metrics.
- Update storage-core to version 0.7.1.
- Update storage-core to version 0.7.2.
- OMPE-95481: Balance the gRPC permission client across all permission service pods via a DNS-discovered, per-request balanced channel with a configurable per-pod connection pool.
- Reduce the default AMQP message batching delay in the Azure Service Bus client.
- Remove support for S3, Azure Blob, and Azure Table metadata backends.
- Expose metadata cache as a separate layer.
- Move URI canonicalization in metadata calls in a separate layer.
- Update storage-core, storage-core-util, and storage-core-protos to versions 0.8.0, 0.8.0, and 0.28.1, respectively.
- Reduce the Metadata interface to batch operations.
- Disable DynamoDB and CosmosDB metadata backends until batch operations have been implemented for them.

- OMPE-19296: Update to version 0.5.0 of the storage protos.
- OMPE-22362: Update to version 0.6.0 of the storage protos.
- OMPE-19733: Implement Rust Service "write" functionality.
- OMPE-20223: Azure Write implementation.
- OMPE-20225: Azure Delete implementation.
- OMPE-20227: Azure Copy implementation.
- OMPE-22913: Azure multi-configuration for container secrets.
- OMPE-20224: S3 Write, implementation.
- OMPE-20226: S3 Delete implementation.
- OMPE-20228: S3 Copy implementation.
- OMPE-22914: S3 multi-configuration for bucket secrets.
- OMPE-20849: integration tests for write operations.
- OMPE-24299: Adjust max concurrency default calculation based on content cache being present.
- OMPE-27391: Add metrics around the concurrency limits in the storage service.
- OMPE-20848: Integration tests for read-only functions.
- OMPE-27828: Add in memory stat cache.
- OMPE-29165: Updated metrics buckets.
- OMPE-26047: vendor all crates into container build for OSRB.
- OMPE-28341: Update to OSRB distroless container v3.1.3 to address CVE-2024-5535.
- OMPE-29728: Update stat cache settings to enable by default.
- OMPE-27543: Make presigned urls expiration time configurable.
- OMPE-25992: Normalized presigned urls expiration for content cache friendly URLs.
- OMPE-24365: [Storage Services Observability] Storage Service request/response to backend per function_id/instance [success/error].
- OMPE-21830: Update storage documentation to explain new bucket settings.
- OMPE-29165: [Storage Services Observability] Enhanced metrics for stat/read, tweak histogram bucket sizes on grafana.
- CDEVS-194: publish containers to MEGA.
- Updated README with configuration options.
- Remove dependency on AWS_REGION for s3 implementation. Region parsed from URL.
- Update to rust 1.82.0. Update crates.
- Make logging to stdout asynchronous.

### Fixed

- OMPE-21190: CVE-2024-6119 - https://security-tracker.debian.org/tracker/CVE-2024-6119
- OMPE-24299: Adjust the max concurrent requests to 30% of the max file descriptors allowed (rlimit nofile).
- OMPE-24299: Fix issue where certain clusters / container runtimes limited max open files to 1024, which
  during large scene loads, the number of sockets in use concurrently would go over that limit and the container
  would abort, causing client to get deadline_timeout errors from reconnecting.
- OMPE-27383: Change default address from `[::]` to `0.0.0.0` because IPv6 not enabled in all clusters.
- Fixed logging of AWS SDK errors and mapping to gRPC status codes.
- Adjusted stdout time format to match Thanos log scraper: `Time_Format %Y-%m-%dT%H:%M:%S.%L%z`
